에이전트들은 서로를 보지 못해서, 각자 통과한 PR이 합쳐지면 서로를 깨뜨립니다. Interlock은 코드가 들어가기 전에 충돌을 막습니다. 실제 Claude Code 에이전트로 돌린 사전 등록 벤치마크(Haiku 5.5, 조건당 60회)에서 Interlock은 60회 모두 병합과 숨은 검사를 통과했습니다(Shepherd 35회, 조정 도구 없음 39회).

Agents can't see each other, so two green PRs can silently undo each other. Interlock coordinates them before code lands. In a pre-registered benchmark with real Claude Code agents (Haiku 5.5, 60 runs per condition), every Interlock run merged and passed hidden checks: 60 of 60, vs 35 with Shepherd and 39 with no tool.

Interlock을 만들고 있습니다.

Building Interlock.

Team PJ에서 CTO로 코드, 아키텍처, 보안 등 엔지니어링 전반을 맡고, 공동창업자 정우진(CEO)과 Interlock을 만들고 있습니다. Interlock은 여러 AI 코딩 에이전트가 한 코드베이스에서 서로의 작업을 깨뜨리지 않게 합니다.

At Team PJ, I lead engineering as CTO (code, architecture, security) and build Interlock with my co-founder Woojin Jung, our CEO. Interlock lets many AI coding agents work on one codebase without breaking each other's work.

Why

에이전트는 빠릅니다. 깨지는 건 여러 에이전트가 한곳에서 일할 때입니다.

Agents are fast. What breaks is several of them working in one place.

한 에이전트가 함수 시그니처를 바꾸는 동안 다른 에이전트는 옛 시그니처로 호출 코드를 씁니다. 각 PR은 따로 통과하고, 충돌은 병합 뒤에야 나타납니다. 저희가 여러 에이전트로 개발하며 직접 겪은 문제이고, 그래서 코드를 파싱해 함수 단위로 막는 도구를 만들었습니다.

While one agent changes a function's signature, another writes calls against the old one. Each PR passes alone, and the conflict shows up only after merging. We hit this ourselves building with several agents at once, so I built a tool that parses code and coordinates at the function level.
